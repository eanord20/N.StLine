# N.StLine — Concept

## 1. Общая идея

**N.StLine** — настольное Windows-приложение для расчёта и оптимизации раскроя длинномерного материала на заданный набор деталей.

Пользователь задаёт:
- материал и длину исходной заготовки;
- потерю на один рез;
- список деталей (наименование, длина, количество).

Программа определяет минимальное количество заготовок, расклад деталей по каждой заготовке, остатки, потери на рез и коэффициент использования материала.

N.StLine — младший родственник N.StCut в экосистеме N.Tools. Он перенимает общую философию, визуальный язык и логику работы, но не копирует архитектуру и не переносит функции, которые относятся только к раскрою листового материала по DXF.

---

## 2. Связь с N.StCut

### 2.1 Общее, которое переносится

- Стек и визуальный язык: WPF .NET 8 + MaterialDesignThemes, светлая/тёмная тема, компактная карточка инструментов, `DataGrid` для табличного ввода.
- Ритм работы пользователя: библиотека материалов → создание задачи → ввод данных → расчёт → проверка результата.
- Двухпанельное окно библиотеки материалов: библиотека слева, материалы текущей задачи справа, стрелки для переноса.
- Стили таблиц: локализованные заголовки, возможность правки ячеек, контекстное меню строки, индикация ошибок.
- Подход к сохранению: JSON-проект `.nstline` и JSON-библиотека материалов в локальных настройках пользователя.
- Локализация EN + UA (как в N.StCut).
- Разделение UI и расчётного движка, тестируемость ядра.

### 2.2 Специфика N.StLine (отличия от N.StCut)

| Аспект | N.StCut | N.StLine |
|---|---|---|
| Предметная область | Раскрой листового материала по DXF | Раскрой длинномерного материала по числовым данным |
| Источник деталей | DXF-файлы, геометрия | Ручной ввод / Excel |
| Главный объект | Лист (длина × ширина) | Заготовка (длина) |
| Геометрия | Контуры, повороты, текстура | Нет геометрии |
| Поиск файлов | Есть | Нет |
| Результат | Карта раскроя на листе, DXF | Таблица/схема раскроя заготовок, DOCX |

### 2.3 Принцип

Пользователь, знакомый с N.StCut, должен сразу понимать интерфейс N.StLine. Общими должны оставаться визуальный язык, логика интерфейса, библиотека материалов и стиль результатов. Различаться — только предметные функции.

## 3. Философия продукта

N.StLine решает конкретную инженерную задачу: сколько и как резать исходные заготовки, чтобы получить нужный набор деталей.

Основной принцип работы:

```
Задача → ввод данных → расчёт → проверка → понятный результат
```

Программа не должна превращаться в сложную систему ради самой архитектуры. Функции добавляются только если они нужны для этой цепочки. В первой версии приоритет:

1. Точность и понятность результата.
2. Простота ввода данных (таблица + Excel).
3. Минимизация числа исходных заготовок.
4. Практичность отчёта.

## 4. Библиотека материалов

Перенимается концепция библиотеки материалов из N.StCut.

### 4.1 Возможности пользователя

- Просматривать библиотеку.
- Создавать новый материал.
- Редактировать существующий материал.
- Удалять материал.
- Выбирать материал.
- Добавлять выбранный материал в текущую задачу.

### 4.2 Модель материала (MVP)

Обязательные поля:

- **Наименование** — пользовательское название (например, `Труба 40×40×4`).
- **Стандартная длина заготовки** — длина исходного материала в миллиметрах (например, `6000`).

В перспективе могут добавляться поля: тип, профиль, марка, единица измерения, комментарий. В MVP добавляются только те свойства, которые используются расчётом. Длина — единственное обязательное числовое свойство.

### 4.3 Хранение

Библиотека сохраняется в JSON-файле в профиле пользователя (`LocalApplicationData`). Формат не зависит от формата проекта N.StCut.

## 5. Исходный материал

После выбора материала пользователь создаёт задачу раскроя.

Пример:

```
Материал: Труба 40×40×4
Длина исходной заготовки: 6000 мм
Длина реза: 3 мм
```

### 5.1 Разделение понятий

- **Длина исходного материала** — длина одной заготовки, мм.
- **Ширина/потеря на один рез** — материал, уходящий на каждый пропил, мм.
- **Длина детали** — полезная длина одной детали, мм.

Эти три понятия никогда не смешиваются в одном параметре. Расчёт ведётся по формуле:

```
Сумма длин деталей на заготовке + (количество деталей × потеря на рез) ≤ длина заготовки
```

---

## 6. Таблица деталей

Основной способ задания деталей — таблица.

### 6.1 Столбцы

| № | Наименование | Длина, мм | Количество |
|---|---|---|---|
| 1 | Стойка | 1250 | 10 |
| 2 | Перемычка | 850 | 20 |
| 3 | Основание | 2400 | 6 |

### 6.2 Возможности

- Добавлять и удалять строки.
- Редактировать данные в ячейках.
- Менять количество (в том числе через кнопки `+` / `-`).
- Копировать и вставлять данные из Excel/таблицы.
- Видеть ошибки валидации прямо в строке.

---

## 7. Импорт из Excel

На первой стадии не создаётся сложный Excel-модуль. Приоритетный сценарий — вставка из буфера обмена.

### 7.1 Формат вставки

Пример строк, скопированных из Excel:

```
Стойка\t1250\t10
Перемычка\t850\t20
Основание\t2400\t6
```

Программа распознаёт столбцы по содержимому:

- Первый столбец — наименование (текст).
- Второй — длина (число).
- Третий — количество (число, по умолчанию 1).

Если в буфере только два числовых столбца, программа интерпретирует их как длина и количество, а наименование оставляет пустым (или генерирует `Деталь 1`, `Деталь 2`…).

### 7.2 Обработка ошибок

При вставке каждая строка проверяется:

- Отсутствует длина → ошибка.
- Отсутствует количество → устанавливается 1 с пометкой.
- Вместо числа введён текст → ошибка.
- Отрицательное или нулевое значение → ошибка.
- Длина детали больше длины исходной заготовки → ошибка.
- Длина реза больше или равна длине заготовки → ошибка задачи.

Ошибки не блокируют вставку целиком: корректные строки добавляются, а некорректные помечаются, чтобы пользователь мог исправить их вручную.

## 8. Главная задача расчёта

### 8.1 Входные данные

- `L` — длина исходной заготовки, мм.
- `K` — потеря на один рез, мм.
- Детали: `(a, qa), (b, qb), (c, qc), …`, где `a` — длина детали, `qa` — количество.

### 8.2 Выходные данные

- Минимальное количество исходных заготовок.
- Распределение деталей по каждой заготовке.
- Остаток каждой заготовки.
- Суммарный расход материала.
- Суммарный остаток.
- Потери на рез.
- Коэффициент использования материала.

### 8.3 Допущения

- Все детали одного типа материала и одной длины заготовки.
- Детали не могут быть короче нуля.
- Рез всегда одинаковой ширины.
- Остаток — это неиспользованный кусок заготовки после последнего реза.

---

## 9. Критерий оптимальности

Перед реализацией алгоритма зафиксирован приоритет критериев.

### 9.1 Основные критерии

1. **Минимальное количество исходных заготовок.**
2. **При равенстве количества заготовок — минимальный суммарный остаток.**

### 9.2 Дополнительные критерии (на будущее)

- Минимизация количества мелких остатков.
- Предпочтение остатков, пригодных для дальнейшего использования.
- Уменьшение количества различных схем раскроя.
- Технологическая простота схем.

В MVP реализуются только основные критерии. Дополнительные фиксируются для последующих версий.

## 10. Учёт реза

### 10.1 Выбранная модель

Для заготовки, на которой размещено `N` деталей, принимается, что требуется `N` резов, включая рез, отделяющий последнюю деталь от остатка.

```
Использованная длина = Σ(длины деталей) + N × K
Остаток = L − Использованная длина
```

### 10.2 Почему именно так

Эта модель консервативна: она не считает остаток «автоматически полезным», потому что для получения последней детали всё равно нужно сделать рез. Если в конкретном технологическом процессе остаток не отрезается, пользователь может задать `K = 0` для последнего реза вручную, но программа по умолчанию считает, что резов столько, сколько деталей.

### 10.3 Проверка

Если `N × K + Σ(детали) > L`, схема считается недопустимой. Если `K ≥ L`, задача считается некорректной.

## 11. Представление результата

### 11.1 Табличный формат

Пример:

| Заготовка | Длина | Рез | Деталь 1 | Деталь 2 | Деталь 3 | Остаток |
|---|---|---|---|---|---|---|
| 1 | 6000 | 3 | 2400 | 1800 | 1200 | 591 |
| 2 | 6000 | 3 | 2400 | 850 | 850 | 1891 |

### 11.2 Компактная строка

```
6000 (3) = 2400 + 1800 + 1200 + 591
```

Число в скобках — потеря на один рез. Формат показывает, как заготовка распадается на детали и остаток.

### 11.3 Текстовый формат с явным учётом реза

```
6000 = 2400 + 3 + 1800 + 3 + 1200 + 3 + 591
```

Этот формат позволяет непосредственно проверить расчёт. Он используется как альтернативный вариант при копировании в Excel/буфер обмена.

РЕЗУЛЬТАТ

## 14. Архитектурное требование

Программа разделяется на независимые части:

```
Material Library
        ↓
Cutting Task
        ↓
Input Data
        ↓
Calculation Engine
        ↓
Optimization
        ↓
Result Model
        ↓
Report / Visualization
```

- UI не содержит математический алгоритм раскроя.
- `Calculation Engine` работает независимо от интерфейса и тестируется отдельно.
- Модели ядра не зависят от WPF.

Планируемые проекты:

- `NStLine.Core` — доменные модели и контракты.
- `NStLine.Cutting` — расчётный движок.
- `NStLine.App` — WPF UI, ViewModels, сервисы приложения.
- `*.Tests` — юнит-тесты.

## 15. Алгоритм оптимизации

### 15.1 Подход для MVP

Для первой версии выбрана стратегия **точный алгоритм + эвристический fallback**.

**Точный расчёт**

Для задач умеренного размера используется алгоритм, способный доказать оптимальность решения. Основной кандидат — генерация всех допустимых схем раскроя одной заготовки с последующим ветвлением/Integer Linear Programming для выбора минимального набора заготовок.

Точный алгоритм стремится доказать:

- минимальное количество заготовок;
- при равенстве — минимальный суммарный остаток.

**Ограничение по времени**

Для сложных задач устанавливается лимит времени расчёта (настраиваемый, по умолчанию 30 секунд). Если точный алгоритм не успел доказать оптимальность:

- сохраняется лучшее найденное решение;
- задача передаётся быстрому эвристическому алгоритму;
- результат помечается как «Лучший найденный вариант».

**Эвристический fallback**

- First Fit Decreasing (FFD);
- Best Fit Decreasing (BFD);
- простой локальный поиск для улучшения полученного решения.

### 15.2 Поведение при большом количестве деталей

Если число возможных схем раскроя превышает порог (`MaxPatternCount`), программа сразу переходит к эвристике, чтобы избежать комбинаторного взрыва.

---

## 16. Важное требование к результату

Программа чётко различает:

- **Оптимальное решение** — только если точный алгоритм доказал оптимальность в рамках ограничений.
- **Лучший найденный вариант** — если оптимальность не доказана или использовалась эвристика.

В интерфейсе не пишется «оптимальный раскрой» без соответствующей гарантии. В подробностях можно показать метод, время и причину fallback.

---

## 17. Тестирование

Создаётся отдельный набор эталонных задач:

1. Одна деталь.
2. Одинаковые детали.
3. Несколько типов деталей.
4. Детали разной длины.
5. Большое количество мелких деталей.
6. Ситуация, где жадный алгоритм даёт плохой результат.
7. Ситуация, где учёт реза меняет результат.
8. Ситуация с полезным остатком.
9. Деталь длиннее исходной заготовки (ошибка).
10. Деталь ровно равна исходной заготовке.
11. Большое количество деталей (проверка fallback).

Для каждой задачи определяются ожидаемые результаты: количество заготовок, остатки, статус точности.

---

## 18. Что НЕ нужно переносить из N.StCut

В N.StLine не переносятся:

- DXF-файлы и импорт DXF.
- Анализ геометрии и развёртки.
- Поиск файлов.
- Определение размеров по геометрии.
- Nesting листа и работа с контурами.
- Поворот геометрических деталей.
- Обработка отверстий.
- CAD-специфическая логика.

N.StLine работает с числовыми данными, а не с геометрией.

1. Изучить N.StCut.
2. Подготовить документ **N.StLine Concept** (настоящий документ).
