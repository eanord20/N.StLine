# N.StLine — MVP Specification

## 1. Цель MVP

Создать первую рабочую версию N.StLine — Windows-приложения для расчёта 1D-раскроя длинномерного материала.

Пользователь должен уметь:

1. Вести библиотеку материалов.
2. Добавить один или несколько материалов из библиотеки; стандартная длина и потеря на рез задаются в материале.
3. Ввести список деталей вручную или вставить из Excel.
4. Получить расчёт: количество заготовок, схему раскроя, остатки, потери на рез, коэффициент использования.
5. Увидеть, является ли результат оптимальным или лучшим найденным вариантом.
6. Скопировать результаты в буфер обмена и экспортировать отчёт в DOCX.
7. Сохранить/загрузить проект.

## 2. Что входит в MVP

### 2.1 Входит

- WPF-приложение .NET 8 с MaterialDesignThemes.
- Светлая/тёмная тема, языки EN + UA.
- Библиотека материалов (CRUD), хранящаяся в JSON в AppData.
- Материал содержит: `Id`, `Name`, `StandardLength`, `CutWidth`.
- Задача раскроя содержит несколько материалов; детали привязаны к материалу через `MaterialId`.
- Карточки материалов над таблицей определяют активный материал для ввода и вставки.
- Таблица деталей активного материала: `№`, `Name`, `Length`, `Quantity`.
- Добавление/удаление строк, редактирование ячеек и Undo для операций с деталями.
- Вставка из буфера обмена (табулятор), распознавание столбцов.
- Валидация строк с индикацией ошибок.
- Кнопка «Рассчитать» с прогрессом и возможностью отмены.
- Расчётный движок: точный алгоритм + эвристический fallback.
- Результат открывается в отдельном независимом окне: общие показатели и вкладки по материалам с таблицами заготовок и схемами.
- Копирование результатов в буфер обмена.
- Экспорт отчёта в DOCX (Xceed.Document.NET).
- Сохранение/загрузка проекта в JSON `.nstline`.
- Набор эталонных тестов.

### 2.2 Не входит

- Тип/профиль/марка материала (подготовлены как future-proof поля, но не используются).
- Импорт Excel из файла (только буфер обмена).
- Экспорт в PDF, Excel, CSV.
- Сложная интерактивная графика.
- Автообновление, инсталлятор, локализация RU.
- Общая библиотека материалов с N.StCut (форматы разные).

## 7. Алгоритм MVP

### 7.1 Общая стратегия

1. Сначала пытаться найти **оптимальное** решение.
2. Если точный поиск выходит за лимит времени или числа схем — переключиться на **эвристику**.
3. В любом случае вернуть `CuttingResult` с правильным статусом.

### 7.2 Точный алгоритм

1. **Генерация схем.** Для одной заготовки перечислить все допустимые мультинаборы деталей `(x1, x2, …, xn)` такие, что:

   ```
   Σ(xi × Li) + (Σxi) × K ≤ BarLength
   ```

   где `xi ≥ 0`, `xi ≤ qi` (остаток по каждой детали).

2. **Выбор схем.** Если число схем ≤ `MaxPatternCount`, решить задачу покрытия спроса минимальным числом заготовок. При равенстве — минимизировать суммарный остаток.

3. **Статус.** Если решение найдено и пространство поиска исчерпано в рамках ограничений, статус = `Optimal`.

### 7.3 Эвристический fallback

Если точный алгоритм не справился за `TimeLimitSeconds` или число схем превысило порог:

1. Развернуть все детали в плоский список копий.
2. Отсортировать по убыванию длины.
3. First Fit Decreasing: каждую копию класть в первую заготовку, где она помещается с учётом потери на рез; иначе открыть новую заготовку.
4. Best Fit Decreasing: альтернатива — класть в заготовку с наименьшим оставшимся запасом.
5. Простой локальный поиск: попытаться перенести детали из наиболее заполненных заготовок и объединить схемы.
6. Статус = `BestFound`.

### 7.4 Модель реза

Для заготовки с `N` размещёнными деталями:

```
CutCount = N
CutLoss  = N × CutWidth
Remainder = BarLength − Σ(part.Length) − CutLoss
```

Если `Remainder < 0`, схема недопустима.

### 8.2 Окно материалов

Аналог `MaterialsWindow` из N.StCut:

- Библиотека материалов хранит `Name`, `StandardLength`, `CutWidth`.
- В главном окне материалы задачи отображаются карточками над таблицей.
- Кнопка `+` добавляет материал из библиотеки в задачу.
- Активная карточка определяет материал новых и вставленных строк.
- Крестик удаляет материал из задачи после подтверждения, если у него есть детали.

### 8.3 Панель результата

- Открывается в отдельном немодальном окне как неизменяемый снимок расчёта.
- Общие итоговые показатели.
- Вкладки по материалам с таблицами заготовок.
- Текстовая схема использует формат `Имя - Длина`.
- Копирование и DOCX-экспорт выполняются из окна результата.

|---|---|---|---|---|---|
| 1 | 6000 | 3 | 2400, 1800, 1200 | 591 | 90.1% |

### 9.2 Текстовая схема

```
6000 (3) = 2400 + 1800 + 1200 + 591
6000 (3) = 2400 + 850 + 850 + 1891
```

### 9.3 Группировка одинаковых схем

```
Схема 1 — 2 шт.
6000 (3) = 2400 + 1800 + 1200 + 591

Схема 2 — 1 шт.
6000 (3) = 2400 + 850 + 850 + 1891
```

### 9.4 Итоговый отчёт (DOCX)

- Заголовок.
- Информация о материале.
- Таблица требуемых деталей.
- Сводка: заготовок, материал деталей, потери на рез, остаток, использование.
- Группированные схемы раскроя.

## 10. Валидация и обработка ошибок

### 10.1 Уровень задачи

- `BarLength` должна быть > 0.
- `CutWidth` должна быть ≥ 0 и < `BarLength`.
- Должна быть выбрана материал.
- Должна быть хотя бы одна деталь.

### 10.2 Уровень строки

- `Name` — строка (может быть пустой).
- `Length` — число > 0.
- `Quantity` — целое число > 0.
- `Length` не должна превышать `BarLength`.

### 10.3 Вставка из Excel

- Построчная валидация.
- Корректные строки добавляются.
- Некорректные помечаются ошибкой, но не блокируют остальные.
- Если не удаётся распознать столбцы, показывается сообщение.

## 11. Эталонные тесты

### 11.1 Набор задач

| № | Описание | Ожидаемый результат |
|---|---|---|
| 1 | Одна деталь 1000, кол-во 3, заготовка 6000, рез 3 | 1 заготовка, остаток 2991 |
| 2 | Деталь 1200, кол-во 5, заготовка 6000, рез 3 | 1 заготовка: 1200×5 + 5×3 = 6015 → 2 заготовки |
| 3 | 2400×2 + 1800×2 + 1200×1, заготовка 6000, рез 3 | 2 заготовки |
| 4 | Жадный плохой: 600, 600, 600, 600, 1000, 1000, 1000, заготовка 1500, рез 0 | Оптимум 4, а не 5 |
| 5 | Учёт реза: 3000×2, заготовка 6000, рез 10 | 2 заготовки, а не 1 |
| 6 | Деталь 7000 при заготовке 6000 → ошибка | Строка помечена, расчёт недоступен |
| 7 | Деталь ровно 5997, рез 3, заготовка 6000 → 1 шт. | Остаток 0 |
| 8 | Большое количество мелких деталей | Проверка fallback |
| 9 | 1250×10, 850×20, 2400×6, заготовка 6000, рез 3 | Эталон из концепции |

### 11.2 Требования к тестам

- Каждый тест проверяет `TotalBarCount` и `TotalRemainder`.
- Для маленьких задач проверяется `Status == Optimal`.
- Для fallback задач проверяется `Status == BestFound`.
