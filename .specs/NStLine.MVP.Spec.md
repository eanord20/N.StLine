# N.StLine — MVP Specification

## 1. Цель MVP

Создать первую рабочую версию N.StLine — Windows-приложения для расчёта 1D-раскроя длинномерного материала.

Пользователь должен уметь:

1. Вести библиотеку материалов.
2. Добавить один или несколько материалов из библиотеки; стандартная длина и потеря на рез задаются в материале.
3. Ввести список деталей вручную или вставить из Excel.
4. Получить расчёт: количество заготовок, схему раскроя, остатки, потери на рез, коэффициент использования.
5. Увидеть, является ли результат оптимальным или лучшим найденным вариантом.
6. Скопировать результаты в буфер обмена и экспортировать отчёт в DOCX.
7. Сохранить/загрузить проект.

## 2. Что входит в MVP

### 2.1 Входит

- WPF-приложение .NET 8 с MaterialDesignThemes.
- Светлая/тёмная тема, языки EN + UA.
- Библиотека материалов (CRUD), хранящаяся в JSON в AppData.
- Материал содержит: `Id`, `Name`, `StandardLength`, `CutWidth`.
- Задача раскроя содержит несколько материалов; детали привязаны к материалу через `MaterialId`.
- Карточки материалов над таблицей определяют материал для новых и вставляемых строк.
- Единая таблица всех деталей задачи сгруппирована по материалам: `№`, `Name`, `Length`, `Quantity`, `Material`; материал строки можно изменить, после чего строка переходит в соответствующую группу.
- Добавление/удаление строк, редактирование ячеек, кнопки `−`/`+` для количества и Undo для операций с деталями.
- Ввод цифры в выделенной ячейке количества заменяет текущее значение первой цифрой и продолжает редактирование как в Excel.
- Вставка из буфера обмена (табулятор), распознавание столбцов.
- Валидация строк с индикацией ошибок.
- Кнопка «Рассчитать» с прогрессом и возможностью отмены.
- Настраиваемые параметры точного поиска: профили Fast (4 с, 25 000 паттернов), Balanced (30 с, 100 000 паттернов, по умолчанию), Deep (90 с, 1 000 000 паттернов) и Custom с ручным вводом лимитов. Ручные лимиты, не совпадающие с пресетами, отображаются как Custom; настройки сохраняются в `settings.json`.
- Профили задают только ресурсы точного поиска, а не гарантируют оптимум. При недоказанной оптимальности показывается `BestFound` с причиной остановки; время и лимит паттернов применяются отдельно к каждому материалу задачи.
- Расчётный движок: точный алгоритм + эвристический fallback.
- Рабочая зона разделена вертикально: ввод слева, последний результат справа; материалы результата показаны последовательными секциями без вкладок.
- Копирование результатов в буфер обмена выполняется из главного окна.
- Отчёт DOCX формируется из главного окна в выбранную папку; папка сохраняется в настройках приложения.
- Сохранение/загрузка проекта в JSON `.nstline`.
- Набор эталонных тестов.

### 2.2 Не входит

- Тип/профиль/марка материала (подготовлены как future-proof поля, но не используются).
- Импорт Excel из файла (только буфер обмена).
- Экспорт в PDF, Excel, CSV.
- Сложная интерактивная графика.
- Автообновление, инсталлятор, локализация RU.
- Общая библиотека материалов с N.StCut (форматы разные).

## 7. Алгоритм MVP

### 7.1 Общая стратегия

1. Сначала пытаться найти **оптимальное** решение.
2. Если точный поиск выходит за лимит времени или числа схем — переключиться на **эвристику**.
3. В любом случае вернуть `CuttingResult` с правильным статусом.

### 7.2 Точный алгоритм

1. **Генерация схем.** Для одной заготовки перечислить все допустимые мультинаборы деталей `(x1, x2, …, xn)` такие, что:

   ```
   Σ(xi × Li) + (Σxi) × K ≤ BarLength
   ```

   где `xi ≥ 0`, `xi ≤ qi` (остаток по каждой детали).

2. **Выбор схем.** Если число схем ≤ `MaxPatternCount`, решить задачу покрытия спроса минимальным числом заготовок. При равенстве — минимизировать суммарный остаток.

3. **Dominance cache.** Для состояния `(patternIndex, remainingDemand)` хранить лучший префикс `(barsUsed, remainderUsed)` и отсекать доминируемые ветви.

4. **Ограничение генерации паттернов по спросу.** Для каждого типа детали счётчик паттерна ограничивается не только геометрией, но и `Quantity`.

5. **Статус.** Если решение найдено и пространство поиска исчерпано в рамках ограничений, статус = `Optimal`.

### 7.3 Эвристический fallback

Если точный алгоритм не справился за `TimeLimitSeconds` или число схем превысило порог:

1. Развернуть все детали в плоский список копий.
2. Отсортировать по убыванию длины.
3. First Fit Decreasing: каждую копию класть в первую заготовку, где она помещается с учётом потери на рез; иначе открыть новую заготовку.
4. Best Fit Decreasing и локальный поиск в текущей версии не реализованы.
5. Статус результата = `BestFound` с причиной (`TimeLimitReached`, `PatternLimitReached` или `ExactNotCompleted`). Отмена пользователем прекращает расчёт без нового результата.

### 7.4 Модель реза

Для заготовки с `N` размещёнными деталями:

```
CutCount = N
CutLoss  = N × CutWidth
Remainder = BarLength − Σ(part.Length) − CutLoss
```

Если `Remainder < 0`, схема недопустима.

## 8. Пользовательский интерфейс

### 8.1 Главное окно

```
┌──────────────────────────────────────────────────────────────┐
│  Файл | Правка | Язык | Тема                                │
├──────────────────────────────────────────────────────────────┤
│  [Материалы] [Вставить Excel] [Очистить]       [Рассчитать] │
├──────────────────────────┬───────────────────────────────────┤
│  Материалы задачи [+]    │ [Копировать] [Сформировать отчёт]│
│  [Труба] [Уголок]        │ Папка отчёта: [...] [Обзор]       │
│  [Undo] [+ строка] [-]   │ Статус и общие показатели        │
│  № | Имя | Длина | Кол.  │ МАТЕРИАЛ 1: итоги                │
│  1 | ... | 1250  | −10+  │ 1. Заготовка ...                 │
│  2 | ... | 850   | −20+  │ МАТЕРИАЛ 2: итоги                │
│  Материал строки [▼]     │ 1. Заготовка ...                 │
├──────────────────────────┴───────────────────────────────────┤
│  Статус / прогресс                                           │
└──────────────────────────────────────────────────────────────┘
```

### 8.2 Окно материалов

Аналог `MaterialsWindow` из N.StCut:

- Библиотека материалов хранит `Name`, `StandardLength`, `CutWidth`.
- В главном окне материалы задачи отображаются карточками над таблицей.
- Кнопка `+` добавляет материал из библиотеки в задачу.
- Активная карточка определяет материал новых и вставленных строк; все строки задачи остаются видимыми.
- Материал существующей строки меняется в столбце `Material`.
- Крестик удаляет материал из задачи после подтверждения, если у него есть детали.

### 8.3 Панель результата

- Последний расчёт отображается в правой части главного окна: общие показатели и последовательные секции материалов без вкладок.
- Каждая секция содержит название материала, количество заготовок, общий остаток, потери на рез, использование и таблицу заготовок.
- После изменения исходных данных результат остаётся видимым с пометкой о необходимости пересчёта; копирование и формирование отчёта блокируются до нового расчёта.
- Текстовая схема использует формат `Имя - Длина единица + Имя - Длина единица`; единица локализуется как `mm` для EN и `мм` для UA.
- Копирование и формирование DOCX выполняются из главного окна.
- Пользователь задаёт папку отчётов; имя файла содержит дату и время, папка сохраняется в `settings.json`.
- После формирования отчёта до завершения приложения доступна кнопка открытия последнего сохранённого DOCX.

## 10. Валидация и обработка ошибок

### 10.1 Уровень задачи

- `BarLength` должна быть конечным числом > 0.
- `CutWidth` должна быть конечным числом ≥ 0 и < `BarLength`.
- Должна быть выбрана материал.
- Должна быть хотя бы одна деталь.

### 10.2 Уровень строки

- `Name` — строка (может быть пустой).
- `Length` — конечное число > 0.
- `Quantity` — целое число > 0.
- `Length + CutWidth` не должна превышать `BarLength`.

### 10.3 Вставка из Excel

- Построчная валидация.
- Корректные строки добавляются.
- Некорректные помечаются ошибкой, но не блокируют остальные.
- Если не удаётся распознать столбцы, показывается сообщение.

## 11. Эталонные тесты

### 11.1 Набор задач

| № | Описание | Ожидаемый результат |
|---|---|---|
| 1 | Одна деталь 1000, кол-во 3, заготовка 6000, рез 3 | 1 заготовка, остаток 2991 |
| 2 | Деталь 1200, кол-во 5, заготовка 6000, рез 3 | 1 заготовка: 1200×5 + 5×3 = 6015 → 2 заготовки |
| 3 | 2400×2 + 1800×2 + 1200×1, заготовка 6000, рез 3 | 2 заготовки |
| 4 | 600×4, 1000×3, заготовка 1500, рез 0 | Оптимум 5: три заготовки для 1000 и две для 600; комбинация 600+1000 недопустима |
| 5 | Учёт реза: 3000×2, заготовка 6000, рез 10 | 2 заготовки, а не 1 |
| 6 | Деталь 7000 при заготовке 6000 → ошибка | Строка помечена, расчёт недоступен |
| 7 | Деталь ровно 5997, рез 3, заготовка 6000 → 1 шт. | Остаток 0 |
| 8 | Большое количество мелких деталей | Проверка fallback |
| 9 | 1250×10, 850×20, 2400×6, заготовка 6000, рез 3 | Эталон из концепции |

### 11.2 Требования к тестам

- Каждый тест проверяет `TotalBarCount` и `TotalRemainder`.
- Для маленьких задач проверяется `Status == Optimal`.
- Для fallback задач проверяется `Status == BestFound`.
- `IndependentOracleTests` независимо перебирает размещение копий деталей для малых задач (целые и десятичные мм), сопоставляет число заготовок и проверяет спрос, пропил и остаток каждой заготовки; отдельно тестируются недопустимые числовые значения и блокировка расчёта при ошибке ввода.
